# توحيد جميع صفحات الإعدادات — V13 (نسخة المرشح للاختبار)

## المرجع

- نقطة البداية المحلية: مشروع V12 بعد تطبيق إصلاحات OCR والنيون، التزام `a5c1684`.
- فرع البناء المرجعي على GitHub: `feature/jh-v12-ocr-recovery-neon-runtime-20261114`، `6168d8ccda4e195cc8f5043fdd11bb3112c2b6aa`.
- هذه التغييرات خاصة بطبقة العرض في نسخة `dev` وتعمل فوق تفضيلات AndroidX الأصلية.
- لم تُضف خيارات أو تفضيلات أو حقول قاعدة بيانات جديدة.

## المكونات الجديدة

- `NeonSettingsStyler.kt`: تصميم شامل للبطاقات في `PreferenceGroupAdapter` المشترك، خلفية ليلية متدرجة، حواف نيون حقيقية بالسماوي والأزرق والبنفسجي والوردي، موجات لمس، عناوين الأقسام، خطوط الثيم ومظهر مفاتيح التشغيل والمنزلقات.
- `NeonSettingsDialogs.kt`: تنسيق اختيارات الإعدادات والتأكيدات بنمط حوار مشترك؛ بناء `non-dev` يحتفظ بطريقته الأصلية.
- `SettingsController.kt`: ربط الثيم بجميع الشاشات الداخلية، استعادة مظهر شريط العنوان الأصلي عند مغادرة الإعدادات، منع تدمير الخلفية بعد التمييز بنتيجة بحث.
- XML: ستة موارد جديدة للألوان والبطاقات والحوار والتموج وشريط العنوان، بالإضافة إلى ملفي `dev` جديدين لنتائج بحث الإعدادات وواجهته.
- تم تبديل استدعاءات بناء الحوارات فقط في `SettingsBackupController`, `SettingsAdvancedController`, `ClearDatabaseController`, `SettingsDownloadController`, و`MatPreference` و`AboutController`، دون تغيير الوظائف أو المستمعين.
- أضيفت مهمة QA جديدة إلى سير عمل GitHub Action دون تعديل أدوات البناء أو مفاتيح التوقيع.

## الأقسام المغطاة بواسطة SettingsController نفسه

- الرئيسية والعامة والمظهر والمكتبة والقارئ والتنزيل والتصفح والمصادر والتتبع والنسخ الاحتياطي والأمان والمتقدمة و«حول التطبيق» والتصحيح، وصفحات البحث داخل الإعدادات.
- صفحات فرعية خارج `SettingsController` مثل بعض الواجهات المستقلة لا يعاد تصميم محتواها تلقائيًا، حفاظًا على سلوكها. تحذيرات مسح قاعدة البيانات تحصل على الثيم المشترك للحوار فقط.
- الواجهة `AboutController` ترث `SettingsController` لذلك ترث تنسيق البطاقات، وحوارها موجود ضمن ثيم الإعدادات الجديد. صفحات تصفية الإضافات التي ترث نفس المكون تظهر أيضًا بنفس البطاقات.

## حماية البيانات والوظائف

- `Settings*Controller.kt`: تعريفات مفاتيح التفضيلات في 16 Controller روجعت دون تغيير، مع ربطها بنفس `PreferencesHelper`/`bindTo` والمداخل وحركات التنقل.
- لم تتغير قواعد البيانات، المفاتيح، القيم الافتراضية، ملفات التسجيل، محركات المصادر/الترجمة/التنزيل، أو إعدادات التوقيع.
- ملفات تخطيط البحث تحت dev تحتفظ بنفس معرّفات Android ViewBinding للنسخة الأصلية.

## نتائج الاختبار

- `qa/v13/validate_settings_neon.py`: نجح، مع تأكيد مواصفات العرض وحفظ مفاتيح الإعدادات ومطابقة IDs.
- فحوص المشروع السابقة V2/V4/V6/V7/V8/V9/V11/V12: تُشغَّل مستقلة قبل اعتماد الإصدار.
- تحليل XML: 727 مورد XML في `app/src` اجتازت فحص الصياغة.
- **لا يوجد بعد نجاح بناء Android لهذا التعديل**: Gradle Wrapper المحلي حاول تنزيل `gradle-9.6.1-bin.zip` ولكن `services.gradle.org` غير قابل للوصول في البيئة الحالية.
- كتابة GitHub من الاتصال الحالي رُفضت برمز `403 Resource not accessible by integration`؛ لذلك لم تُجرَ اختبارات GitHub Actions على V13 ولم يتم إنتاج APK.
- **اختبار الهاتف غير منفذ**: لا توجد لقطات شاشة حقيقية لشاشات V13 ولا اختبار فتح/حفظ/إعادة تشغيل.

## بوابات الاعتماد المطلوبة قبل التسليم

1. رفع الفرع المستقل وتفعيل Quality Gate الخاص به على GitHub.
2. نجاح `testDevDebugUnitTest` و`verifySingleArm64DevApk` ووجود APK واحد سليم.
3. التأكد أن كل قسم يفتح ويحفظ الإعدادات ويحتفظ بها بعد إعادة تشغيل التطبيق.
4. التأكد من رسائل النسخ الاحتياطي والحذف وعدم فقدان أية بيانات، مع عدم إجراء الحذف أثناء الاختبار على بيانات فعلية.
5. مقارنة لقطات صفحة الإعدادات الرئيسية والفرعية والنوافذ والبحث، العربية وRTL، والوضع الأفقي والشاشة الصغيرة.
6. فحص توافق توقيع APK مع النسخة المثبتة قبل أي محاولة تحديث داخلية.

**الحالة:** تطوير مرئي منفذ ومحفوظ محليًا، لكن غير معتمد للتسليم النهائي بدون البناء وQA الجهاز.
