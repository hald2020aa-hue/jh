# تطوير TachiyomiJ2K — حزمة المراحل 1 و2 و3

**النوع:** مصدر برمجي معدل (unofficial development fork)، وليس تطبيق APK نهائي.

**المرجع:** الملف المرفوع من المستخدم `tachiyomiJ2K-master.zip`، ثم تعديلات مرحلة التطوير السابقة؛ لا توجد تغييرات على مستودع GitHub الأصلي.

## المرحلة الأولى — الاستقرار والأمان
- حفظ تحديد الفصول/العناوين المرسلة إلى عامل تحديث المكتبة الكبيرة في ملف خاص دائم بدل متغير `static` يضيع عند قتل العملية. المجموعات الصغيرة تُمرر في `WorkManager Data`.
- الاحتفاظ بملف الاختيار حتى اكتمال عمل WorkManager حتى يمكن إعادة المحاولة عند إغلاق العملية، ثم حذفه، وتنظيف الملفات المهجورة القديمة.
- تحسين الأداء عند تحديد آلاف عناوين المكتبة باستعمال `HashSet` بدل البحث الخطي المتكرر.
- تهيئة SourceManager الاحتياطية عبر `computeIfAbsent` الذرية بدلاً من إنشاء مصادر مكررة في التزامن.
- ضبط حد **128 MiB** للنسخة الاحتياطية **بعد** فك gzip، وتحرير المدخلات في حالات الخطأ لمنع استهلاك الذاكرة غير المقيد.
- الحفاظ على إصلاحات المرحلة السابقة للإضافات وتحديثات المكتبة وفك AVIF والتحقق من التنزيلات والملفات المضغوطة.

## المرحلة الثانية — القارئ والأجهزة القابلة للطي
- إصلاح عودة عرض عناصر القارئ إلى العرض الكامل عند انتقال الجهاز من مفصلة عمودية فاصلة إلى وضع الشاشة العادي؛ مع مراعاة شريط التمرير العمودي.
- ضبط الحد الأقصى للصور المتحركة التي تُحمّل في الذاكرة على **64 MiB**، وإظهار حالة خطأ عند تجاوزه، بدلاً من قراءة تدفق غير محدود.
- الاحتفاظ بخيارات القراءة الموجودة أصلًا مثل عرض صفحتين وWebtoon وRTL، دون إعادة تنفيذها.

## المرحلة الثالثة — المكتبة والبحث والإحصائيات
- فلتر جديد في بحث المكتبة: `dup:yes` لإظهار عناوين يشتبه تكرارها بين **مصدرين مختلفين**، و`dup:no` لعكس الفلتر؛ أُضيف إلى لوحة فلاتر البحث.
- التطابق محافظ؛ لا تُحذف أو تُدمج العناوين تلقائيًا. يُنظر إلى اسم العنوان بعد توحيد التشكيل والهمزات والرموز البسيطة.
- بحث عنوان أكثر تساهلًا مع التشكيل والهمزات العربية والفواصل وعلامات الترقيم.
- إحصاء جديد لعدد الفصول ذات **آخر قراءة مسجلة خلال 7 أيام**، وعدد الأيام المميزة التي تحتوي على آخر قراءة مسجلة؛ هذا **ليس** سجلًا كاملًا لكل جلسة قراءة.
- تسميات واجهة جديدة بالعربية والإنجليزية؛ بقية اللغات تستعمل النص الإنجليزي الافتراضي.

## اختبارات نُفذت بالفعل
- `bash qa/run_local_tests.sh`: **64/64** فحص منطق Kotlin + **5/5** فحص ربط فعلي لفلتر البحث باستخدام نماذج بديلة (stubs) للبيانات.
- `python3 qa/static_integration_checks.py`: **10/10** فحوص بنيوية وXML وSQL.
- `git diff --check`: ناجح.
- تم تنفيذ اختبار SQLite للصيغة المستعملة بإحصائيات آخر سبعة أيام.

## ما لم يُختبر ولم يكتمل
- **لم ينجح بناء APK**: تعذر تنزيل Gradle 9.6.1 من `services.gradle.org` بسبب `UnknownHostException`، ولا يتوفر Android SDK في بيئة العمل الحالية.
- اختبارات Android/JUnit المضافة تحتاج Gradle وAndroid SDK ولم تُنفذ.
- لم يُختبر فعليًا الأداء على هواتف Galaxy Z Fold، فك AVIF، استعادة النسخ الاحتياطية، الإضافات، التصفح عبر WebView، التنزيلات طويلة الأمد أو بيئة أندرويد حقيقية.
- لم تُنفذ منظومة مزامنة سحابية (تحتاج خدمة/بنية خلفية وسياسة صلاحيات)، أو تعريب كامل لجميع الشاشات، أو لوحة تشخيص مصادر كاملة، أو تدقيق أمني شامل للأذونات والشهادات.
- **لا يوجد ملف APK صالح للتثبيت أو إصدار Release موقع**. لا تستبدل تطبيقك الأساسي بهذه الشفرة قبل إجراء البناء والفحص على أجهزة اختبار.

## خطوات البناء والتحقق على ويندوز 10/11
1. ثبّت Android Studio وAndroid SDK Platform **API 37** (مع Native CMake/NDK المطلوب في Gradle) وJDK 21 واتصال إنترنت.
2. فك هذه الحزمة داخل مجلد بسيط بالإنجليزية، مثل `C:\Projects\J2KEnhanced`.
3. افتح PowerShell داخل المجلد وشغل: `powershell -ExecutionPolicy Bypass -File .\scripts\build-development-windows.ps1`.
4. إذا نجح Gradle واختبارات JUnit، اعثر على ملفات Dev Debug في `app\build\outputs\apk\dev\debug`.
5. اختبر مصدرًا صالحًا، عدة إضافات، مكتبة كبيرة، النسخ الاحتياطية، ملفات CBZ، وطي الشاشة قبل اعتماد النشر.

## البناء على GitHub Actions
رفع الملفات إلى **مستودع يملكه المستخدم** وتشغيل `Quality gate (independent fork)` عبر `workflow_dispatch` يُجري فحص XML وSQL واختبارات Android وبناء Dev Debug، ويرفع APK التجريبي إذا نجح البناء؛ لم يُشغّل هذا المسار في جلستنا الحالية.

## الترخيص
المشروع مشتق من TachiyomiJ2K ويحافظ على ترخيص Apache-2.0 وحقوق المؤلف الأصلية. النسخة غير رسمية وغير مرتبطة بمطوري المصدر.
